# ADR-007: Run natively under systemd, no container runtime

- **Date:** 2026-11-14
- **Status:** Accepted
- **Supersedes:** [ADR-005](ADR-005.md) (rootful Podman)
- **Deciders:** project owner

## Context

ExamDump Pro ran as four containers under rootful Podman on a single host:
nginx, a Next.js web server, a Fastify API and PostgreSQL 16. That topology
worked, but the container layer existed only to package four processes that all
run on the same machine. It added a second storage tree, an image registry to keep
current, a compose file that drifted from the actual runtime, and a class of
failure the application could not observe — most visibly a cached container IP
that made nginx return 502 while the API was healthy.

## Decision

Run the application directly on the host under **systemd**, with **native
PostgreSQL 16**.

```
nginx.service           :80/:443   reverse proxy, TLS
examdump-web.service    :3000      Next.js standalone, user examdump
examdump-api.service    :4000      Fastify, user examdump
postgresql.service      :5432      PostgreSQL 16, user postgres
```

- The API and web server bind to **loopback only**; nginx is the sole public
  listener.
- Both application services run as the unprivileged `examdump` user with
  systemd hardening (`NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`,
  `PrivateTmp`).
- Secrets come from Doppler and land in `/etc/examdump-pro/production.env`
  (mode 0640, `root:examdump`).
- Restart policy is `Restart=always`, so a crash is recovered without an operator.
- Database backups run through the same `pg_dump` wrapper as before, now against
  the local cluster.

## Migration

Performed as a single controlled cutover from a verified `pg_dump`: native
PostgreSQL was installed and restored, the API and web services were started on
loopback and verified, nginx was switched to the host installation, and only then
were the containers removed. The container database was never the only copy of the
data at any point.

## Consequences

**Good**

- One fewer abstraction between the application and the operating system; logs go
  straight to the journal and `systemctl status` shows the real process.
- Deployment is copying build output and restarting a unit.
- Removing the container layer reclaimed ~2.3 GB of storage.
- No image registry or compose file to keep in sync with the code.

**Bad**

- Node and its dependency tree are now installed on the host and must be patched
  like any other system package.
- Two services share one runtime directory (`/opt/examdump-pro`), where containers
  gave stronger isolation.
- SELinux needs correct labelling for nginx to read the certificates and reach
  loopback ports.

## Host dependency that remains

Rootless Podman stays installed for **Omniroute** (`omniroute`,
`omniroute-redis`), an unrelated application in the `opc` user's rootless store.
ExamDump does not use it. It must not be removed without first migrating
Omniroute.
